ISSUE #4: Very Low Confidence Scores Across ALL Queries
──────────────────────────────────────────────────────────────────────
  Even correct answers show low confidence:
    - "How many sick days?" → Correct answer "12 days" but only 40%
    - "What changed?" → 22%
    - "2days?" → 11%
    - "Dubai remote?" → 13% (panel) vs 62% (chat)
    - "Home office allowance?" → 59%
  Root Cause: Confidence formula is (1 - distance/2) * 100. But 
              all-MiniLM-L6-v2 produces normalized vectors where L2 
              distances range 0-4, not 0-2. Formula assumes wrong range.
  Impact: Makes system look unreliable even when answers are correct.

ISSUE #1 FIX: Sentence-aware chunking + Cosine similarity + Hybrid search
──────────────────────────────────────────────────────────────────────
  Files changed: app/config.py, app/ingestion.py, app/retrieval.py
  
  1. Replaced character-based 500-char chunking with SENTENCE-AWARE chunking.
     Chunks now respect sentence boundaries — never cuts mid-sentence.
     Uses regex to split on sentence endings (period+capital, paragraph breaks).
  
  2. Switched FAISS from IndexFlatL2 (L2 distance) to IndexFlatIP (Inner Product).
     For normalized vectors, inner product = cosine similarity.
     Scores now in [0, 1] range → accurate confidence percentages.
  
  3. Added HYBRID retrieval: 70% semantic (FAISS cosine) + 30% keyword matching.
     Keyword function checks if query terms appear in chunk text.
     This catches exact term matches like "ChatGPT" that embeddings may miss.
  
  4. Embeddings normalized with faiss.normalize_L2() before adding to index.
     Query vectors also normalized before searching.
  
  5. Retrieval now fetches top_k*8 candidates and re-ranks by hybrid score.

ISSUE #16: Confidence too low even for perfect answers (51% for sick days)
──────────────────────────────────────────────────────────────────────
  Query: "How many sick days do employees get per year?"
  Answer: Correct — "12 days" from HR_Policy.pdf
  Confidence shown: Only 51% — should be much higher (80-90%+)

  Root Cause: The confidence is an AVERAGE of ALL retrieved chunks.
  We retrieve top 5 chunks. The #1 chunk might score 68%, but chunks
  #3, #4, #5 (from unrelated docs) score 30-40%, dragging the average
  down. The final confidence = average of all 5 = ~51%.

  The problem: Confidence should reflect the BEST match quality,
  not the average of all retrieved chunks. When the top chunk is 
  highly relevant, the user should see high confidence.

  Fix options:
    A) Use MAX confidence instead of average
    B) Use weighted average (top chunks weighted more)
    C) Use top-1 confidence for Q&A, average for compliance
    D) Only average chunks above a relevance threshold

  Recommended: Use MAX of top-2 chunks' confidence. This way,
  if the best 2 chunks are 68% and 62%, confidence = 68%.
  Irrelevant chunks from other docs don't drag it down.
